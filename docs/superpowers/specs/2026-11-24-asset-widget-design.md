# AssetGlance: 홈 화면 시세 위젯 설계

날짜: 2026-11-24

## 왜 만드나

사용자는 달러·엔화 환율, 비트코인, 관심 주식 가격을 자주 확인한다. 지금은 매번 앱을 열고, 비밀번호를 누르고, 종목을 검색해야 해서 귀찮다. 갤럭시 홈 화면에 위젯을 두고 **아무것도 누르지 않아도** 가격과 오늘 변화가 보이게 하는 것이 목적이다. 기존 홈 화면의 듀오링고 위젯처럼 그냥 놓여 있는 물건이어야 한다.

## 목표

- 홈 화면에서 다섯 자산의 현재가와 오늘 변화(금액과 %)를 한눈에 본다.
- 최소 하루 한 번은 반드시 갱신된다. 실제로는 15분마다 자동 갱신한다.
- 위젯을 누르면 그 자리에서 바로 새로고침된다.
- 사용자가 폰만으로 설치하고 업데이트할 수 있다. PC는 쓰지 않는다.

## 하지 않는 것

- 플레이스토어 배포. 사용자 본인의 갤럭시 한 대에만 설치한다.
- 폰에서 종목을 검색하거나 추가·삭제하는 화면. 목록은 코드에 고정하고, 바꿀 때는 코드를 고쳐 새 APK를 만든다.
- 차트, 알림, 가격 경보, 포트폴리오나 계좌 연동.
- 위젯을 눌렀을 때 다른 앱(증권 앱 등) 열기.
- 토스증권 API. 검토 후 쓰지 않기로 했다(아래 "검토한 대안" 참고).

## 실패로 볼 것 (기술적으로는 돌아가더라도)

- 위젯에 숫자가 나오지만 몇 시간째 그대로인데, 오래된 값이라는 걸 알 수 없는 경우.
- 업데이트할 때마다 기존 앱을 지우고 다시 깔아야 하는 경우(서명이 매번 바뀜). 위젯도 다시 배치해야 해서 사용자가 쓰지 않게 된다.
- 설치 과정에 PC가 필요한 경우.

## 내가 정한 것 (사용자가 반대하지 않았지만 명시적으로 고른 건 아님)

- **단위**: 달러는 1달러당 원, 엔화는 100엔당 원, 비트코인은 원화, 두 주식은 달러.
- **"오늘 변화"의 기준**:
  - 비트코인: 업비트 API의 `signed_change_*` 그대로. 업비트의 전일 종가(`prev_closing_price`, 하루 경계는 09:00 KST) 대비다.
  - 환율: 야후 일봉의 **직전 완료된 거래일 종가** 대비. `range=1d`의 `chartPreviousClose`는 환율에서 직전 일봉 종가와 다르다(검토 중 확인: KRW=X 1342.02 vs 1344.31).
  - 주식: 미국 **정규장** 기준, 직전 정규장 종가 대비. 프리마켓·애프터마켓·주간거래 가격은 쓰지 않는다. 그래서 한국 낮이나 주말에는 직전 정규장의 변화가 그대로 보이고, 증권 앱의 주간거래 가격과는 다를 수 있다.
  - 미국 정규장이 닫혀 있는 동안 주식 타일에 작은 `마감` 표시를 붙여, 지금 움직이는 값이 아니라는 걸 알 수 있게 한다.
- **색**: 한국식. 상승은 빨강 ▲, 하락은 파랑 ▼. 화면에 **표시된(반올림된) 값**이 0이면 회색으로 기호 없이 표시한다.
- **위젯 배경**: 테마와 관계없이 항상 어두운 반투명. 사용자 바탕화면이 어둡다.
- **인터넷이 끊기거나 출처가 실패하면**: 마지막으로 성공한 값을 그대로 두고, 실패한 타일은 흐리게 표시한다. 갱신 칸은 마지막으로 **모두 성공한** 시각을 날짜와 함께 보여준다(`11/24 16:21`). 주기 작업이 아예 안 돌면 위젯이 스스로 다시 그려질 수 없으므로, 날짜가 있어야 하루 지난 값인지 알 수 있다. 최초 실행 전처럼 값이 아예 없으면 가격 자리에 `–`를 둔다.
- **런처 화면**: 아주 작은 화면 하나를 둔다. 위젯 추가 방법 한 줄과, 배터리 설정을 "제한 없음"으로 바꾸는 화면을 여는 버튼만 있다. 삼성 절전 기능이 앱을 재우면 "최소 하루 한 번"을 지킬 수 없기 때문이다.
- **패키지 이름**: `com.assetglance.widget`. 업데이트가 덮어쓰기로 되려면 이 이름과 서명 키, 위젯 클래스 이름을 앞으로 바꾸지 않는다.
- **배포 경로**: GitHub Actions가 APK를 빌드해 이 저장소의 GitHub Release에 올린다. 저장소가 공개라서 폰 브라우저에서 로그인 없이 받을 수 있다.
- **서명**: 빌드마다 같은 키로 서명해야 덮어쓰기 업데이트가 된다. 이 앱 전용 디버그 키스토어를 저장소에 커밋하고 CI가 그 키로 서명한다.
  - 한계: 공개 저장소라 누구나 같은 키로 서명한 APK를 만들 수 있다. 앱 권한이 인터넷뿐이고 사용자는 자기 Release 페이지에서만 받으므로 위험은 낮다고 판단했다. 걱정되면 키를 GitHub Secrets로 옮기면 된다.

## 시세 출처 상세

둘 다 API 키가 없다. 2026-11-24에 이 환경에서 실제로 호출해 응답을 확인했다.

**업비트** (공식 공개 API)
- `GET https://api.upbit.com/v1/ticker?markets=KRW-BTC`
- 사용 필드: `trade_price`(현재가), `signed_change_price`(변화 금액), `signed_change_rate`(변화율, 0.0199 = 1.99%)

**야후 파이낸스** (비공식. 예고 없이 바뀌거나 막힐 수 있다)
- `GET https://query1.finance.yahoo.com/v8/finance/chart/{심볼}?range=5d&interval=1d`
- 브라우저 같은 `User-Agent` 헤더를 붙인다. 검토 중 첫 호출이 HTTP 429로 거부된 적이 있다. 짧은 재시도(백오프)와, 실패 시 `query2.finance.yahoo.com` 호스트로 넘어가는 처리를 둔다.
- 사용 필드: `meta.regularMarketPrice`(현재가). 전일 종가는 일봉 배열(`timestamp`, `indicators.quote[0].close`)에서 **오늘 봉 바로 앞의 완료된 봉의 종가**를 쓴다. 변화는 직접 계산한다.
- 심볼: 달러 `KRW=X`, 엔화 `JPYKRW=X`(1엔당 원이므로 ×100), 엔비디아 `NVDA`, 버크셔B `BRK-B`
- 확인한 값(16:21 KST): KRW=X 1344.22, JPYKRW=X 8.415, NVDA 165.05(직전 종가 125.53), BRK-B 572.36(570.0). 환율의 직전 일봉 종가는 KRW=X 1344.31, JPYKRW=X 8.457.
  - NVDA +31%는 야후 일봉과 일치하지만 하루 변화로는 믿기 어렵다. 빌드 중에 다른 출처와 한 번 대조해, 계산 방식 문제인지 야후 데이터 문제인지 확인한다.
- 야후 값은 은행 고시 환율과 몇 원 다를 수 있다. 사용자에게 설명했고 받아들였다.

출처별 가져오기 코드는 한곳에 모아서, 야후가 막히면 그 부분만 다른 출처로 바꿀 수 있게 한다.

## 위젯 모양

- 4×2칸, 3열×2행 타일. 순서: 달러, 엔화, 비트코인 / 엔비디아, 버크셔B, 갱신 칸.
- 사용자 홈 화면은 스크린샷상 가로 4칸 격자라서, 4칸 위젯은 화면 폭 전체이고 타일 하나는 약 100dp 폭이다. 글씨 크기 설정이 커도 잘리지 않고 줄어들어 맞도록 만든다(잘린 숫자는 버그).
- 자산 타일: 첫 줄에 아이콘(약 20dp, 원형) + 이름, 둘째 줄에 굵은 가격, 셋째 줄에 색 있는 변화. 주식 타일은 장이 닫혀 있으면 이름 옆에 작은 `마감`.
- 갱신 칸: 오른쪽 아래 정렬. `11/24 16:21` + 새로고침 아이콘, 그 아래 "눌러서 새로고침".
- 새로고침 중에는 갱신 칸 시각 자리에 "갱신 중…"을 표시한다. 앱 프로세스가 죽어도 이 표시가 남지 않게, 일정 시간이 지나면 이전 상태로 되돌린다.

숫자 형식:

| 자산 | 가격 | 변화 |
|---|---|---|
| 달러 | `1,344.22` | `▲2.20 (0.16%)` |
| 엔화 100엔 | `841.50` | `▼0.10 (0.01%)` |
| 비트코인 | `8,206만` (만 원 단위, 반올림) | `▼166만 (1.99%)` |
| 엔비디아 | `$165.05` | `▲39.52 (31.48%)` |
| 버크셔B | `$572.36` | `▲2.36 (0.41%)` |

- %는 소수 둘째 자리, 부호는 ▲/▼ 기호로만 표시한다.
- 화살표와 색은 **표시된 반올림 값**으로 정한다. 비트코인 변화가 5천 원 미만이라 `0만`이 되거나, 변화율이 `0.00%`가 되면 회색, 기호 없음.
- 비트코인이 1억 원을 넘어도 `14,305만`처럼 만 단위로 쓴다.
- 폰의 언어·지역 설정과 관계없이 항상 이 형식(쉼표 천 단위, 점 소수)으로 쓴다.

## 갱신 방식

- 15분마다 주기 작업으로 전체 시세를 가져온다(안드로이드 주기 작업의 최소 간격). 네트워크가 있을 때만 실행하고, 재부팅 후에도 유지한다.
- 위젯 탭 시 즉시 한 번 가져온다.
- 위젯을 처음 홈 화면에 놓을 때도 즉시 한 번 가져온다.
- 화면이 꺼진 동안 삼성 절전 기능 때문에 갱신이 늦춰지는 건 받아들인다. 화면을 켜고 탭하면 바로 갱신된다.
- "최소 하루 한 번"은 앱 배터리 설정이 "제한 없음"이고 절전 앱 목록에 없을 때만 지켜진다. 설치 안내에 이 단계를 넣고, 런처 화면에서 바로 열 수 있게 한다.

## 업데이트

- 빌드마다 버전 코드를 올린다(CI 실행 번호 사용).
- 패키지 이름, 서명 키, 위젯 클래스 이름은 바꾸지 않는다. 위젯 클래스 이름이 바뀌면 홈 화면에 놓인 위젯이 사라진다.
- 앱이 업데이트된 직후 위젯을 다시 그리고 주기 작업을 다시 등록한다. 그러지 않으면 "위젯을 불러올 수 없음"이 뜰 수 있다.

## 제약

- 폰만으로 설치·업데이트할 수 있어야 한다.
- 앱 권한은 인터넷(그리고 재부팅 후 주기 작업 유지에 필요하면 그것)만 쓴다.
- 의존성은 최소로 한다. 플랫폼 기능(HTTP, JSON 파싱, 작업 예약, RemoteViews)으로 되는 건 라이브러리를 추가하지 않는다.
- 비밀값(API 키 등)은 없다.

## 검토한 대안

- **토스증권 Open API**: 사용자가 키를 줄 수 있다고 했으나 쓰지 않기로 함. 등록된 고정 IP에서만 호출할 수 있어 모바일 네트워크의 폰에서는 막힌다(토스 FAQ에 명시). 비트코인과 엔화 환율이 없다. 같은 키로 주문까지 가능해 폰에 넣기 위험하다.
- **위젯 모양 A(목록형), C(한 줄 띠형)**: 시안으로 비교 후 B를 선택.

## 빌더에게 맡기는 것

- 언어와 빌드 설정(Kotlin, Gradle, minSdk/targetSdk 등)
- 주기 작업에 쓸 API(JobScheduler, WorkManager 등)와 탭 새로고침 구현 방식
- 위젯 레이아웃의 정확한 dp, 글꼴 크기, 모서리 반경. 시안의 느낌(어두운 반투명, 둥근 타일)을 따른다.
- 로고 이미지 출처와 형식(앱에 내장, 인터넷 없이 표시)
- 런처 화면의 모양(내용은 위에 정함)
- GitHub Actions 워크플로 세부(어떤 브랜치 푸시에 Release를 갱신할지 등)
- 야후 재시도 횟수와 간격, 여러 심볼을 한 번에 받는 엔드포인트(`v8/finance/spark`) 사용 여부
- 시세 계산 로직에 대한 작은 자체 테스트

## 사용자 답변 대기

1. **설치·업데이트 때 삼성 "자동 차단"**: One UI 6.1.1 이후 출시된 갤럭시는 자동 차단이 기본으로 켜져 있어 브라우저로 받은 APK 설치를 막는다. One UI 8.5는 끈 뒤 일정 시간이 지나면 다시 켤 수 있다는 보도가 있다. 업데이트마다 잠깐 끄고 설치하는 과정을 받아들일지.
2. **버크셔 해서웨이 로고**: 버크셔에는 심볼 로고가 없고 "Berkshire Hathaway Inc." 글자 로고뿐이라 20dp 동그라미에서는 읽을 수 없다. 엔비디아는 눈 모양 심볼이 있어 그대로 쓸 수 있다. 버크셔 자리에 무엇을 넣을지.

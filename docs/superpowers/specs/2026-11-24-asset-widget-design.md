# AssetGlance: 홈 화면 시세 위젯 설계

날짜: 2026-11-24

## 왜 만드나

사용자는 달러·엔화 환율, 비트코인, 관심 주식 가격을 자주 확인한다. 지금은 매번 앱을 열고, 비밀번호를 누르고, 종목을 검색해야 해서 귀찮다. 갤럭시 홈 화면에 위젯을 두고 **아무것도 누르지 않아도** 가격과 오늘 변화가 보이게 하는 것이 목적이다. 기존 홈 화면의 듀오링고 위젯처럼 그냥 놓여 있는 물건이어야 한다.

## 목표

- 홈 화면에서 다섯 자산의 현재가와 오늘 변화(금액과 %)를 한눈에 본다.
- 최소 하루 한 번은 반드시 갱신된다. 실제로는 15분마다 자동 갱신한다.
- 위젯을 누르면 그 자리에서 바로 새로고침된다.
- 사용자가 폰만으로 설치하고 업데이트할 수 있다. PC는 쓰지 않는다.

## 하지 않는 것

- 플레이스토어 배포. 사용자 본인의 갤럭시 한 대에만 설치한다.
- 폰에서 종목을 검색하거나 추가·삭제하는 화면. 목록은 코드에 고정하고, 바꿀 때는 코드를 고쳐 새 APK를 만든다.
- 차트, 알림, 가격 경보, 포트폴리오나 계좌 연동.
- 위젯을 눌렀을 때 다른 앱(증권 앱 등) 열기.
- 토스증권 API. 검토 후 쓰지 않기로 했다(아래 "검토한 대안" 참고).

## 실패로 볼 것 (기술적으로는 돌아가더라도)

- 위젯에 숫자가 나오지만 몇 시간째 그대로인데, 오래된 값이라는 걸 알 수 없는 경우.
- 업데이트할 때마다 기존 앱을 지우고 다시 깔아야 하는 경우(서명이 매번 바뀜). 위젯도 다시 배치해야 해서 사용자가 쓰지 않게 된다.
- 설치 과정에 PC가 필요한 경우.

## 사용자가 정한 것

| 항목 | 결정 |
|---|---|
| 기기 | 사용자의 삼성 갤럭시 (One UI, 최신 안드로이드) 한 대 |
| 설치 | 폰에서 APK를 직접 내려받아 설치 |
| 자산 | 달러, 엔화, 비트코인, 엔비디아(NVDA), 버크셔 해서웨이 B(BRK-B) |
| 표시 | 현재가 + 오늘 변화. 변화는 금액과 %를 같이 |
| 갱신 | 최소 매일. 15분 자동 갱신과 탭 새로고침에 동의 |
| 탭 동작 | 위젯 어디를 눌러도 즉시 새로고침 |
| 시세 출처 | 비트코인은 업비트, 나머지는 야후 파이낸스 |
| 모양 | 시안 B(타일형). 4×2칸, 3열×2행 타일 6개 중 5개는 자산, 1개는 갱신 시각 |
| 아이콘 | 달러·엔화는 국기, 비트코인은 ₿ 마크, 엔비디아·버크셔는 **진짜 회사 로고** |
| 목록 변경 | 앱 안에 고정. 바꿀 때는 새로 빌드 |

시안: https://claude.ai/artifact/3UAwfkQ7KFWy6KLeWjy5BE (위쪽 "B안 + 아이콘"이 확정안. 로고 두 개는 아직 임시 배지)

## 내가 정한 것 (사용자가 반대하지 않았지만 명시적으로 고른 건 아님)

- **단위**: 달러는 1달러당 원, 엔화는 100엔당 원, 비트코인은 원화, 두 주식은 달러.
- **"오늘 변화"의 기준**: 주식은 전 거래일 종가, 비트코인은 업비트 기준(매일 09:00 KST 시작가 대비, 업비트 API의 `signed_change_*` 그대로), 환율은 야후의 전일 종가.
- **색**: 한국식. 상승은 빨강 ▲, 하락은 파랑 ▼, 변화 0은 회색으로 기호 없이 표시.
- **위젯 배경**: 테마와 관계없이 항상 어두운 반투명. 사용자 바탕화면이 어둡다.
- **인터넷이 끊기거나 출처가 실패하면**: 마지막으로 성공한 값을 그대로 두고, 실패한 타일은 흐리게 표시한다. 갱신 시각 칸은 마지막으로 **모두 성공한** 시각을 보여준다. 최초 실행 전처럼 값이 아예 없으면 가격 자리에 `–`를 둔다.
- **배포 경로**: GitHub Actions가 APK를 빌드해 이 저장소의 GitHub Release에 올린다. 저장소가 공개라서 폰 브라우저에서 로그인 없이 받을 수 있다.
- **서명**: 빌드마다 같은 키로 서명해야 덮어쓰기 업데이트가 된다. 이 앱 전용 디버그 키스토어를 저장소에 커밋하고 CI가 그 키로 서명한다.
  - 한계: 공개 저장소라 누구나 같은 키로 서명한 APK를 만들 수 있다. 앱 권한이 인터넷뿐이고 사용자는 자기 Release 페이지에서만 받으므로 위험은 낮다고 판단했다. 걱정되면 키를 GitHub Secrets로 옮기면 된다.

## 시세 출처 상세

둘 다 API 키가 없다. 2026-11-24에 이 환경에서 실제로 호출해 응답을 확인했다.

**업비트** (공식 공개 API)
- `GET https://api.upbit.com/v1/ticker?markets=KRW-BTC`
- 사용 필드: `trade_price`(현재가), `signed_change_price`(변화 금액), `signed_change_rate`(변화율, 0.0199 = 1.99%)

**야후 파이낸스** (비공식. 예고 없이 바뀌거나 막힐 수 있다)
- `GET https://query1.finance.yahoo.com/v8/finance/chart/{심볼}?range=1d&interval=1d`
- 브라우저 같은 `User-Agent` 헤더가 없으면 거부될 수 있다.
- 사용 필드: `chart.result[0].meta.regularMarketPrice`(현재가), `meta.chartPreviousClose`(전일 종가). 변화는 직접 계산한다.
- 심볼: 달러 `KRW=X`, 엔화 `JPYKRW=X`(1엔당 원이므로 ×100), 엔비디아 `NVDA`, 버크셔B `BRK-B`
- 확인한 값(16:21 KST): KRW=X 1344.22 / 전일 1342.02, JPYKRW=X 8.415 / 8.416, NVDA 165.05 / 125.53, BRK-B 572.36 / 570.0
  - NVDA는 전일 대비 +31%로 이상해 보이지만 `range=5d` 일봉 종가(…145.98, 125.53, 165.05)와 일치한다. 야후가 준 값 그대로다.

출처별 가져오기 코드는 한곳에 모아서, 야후가 막히면 그 부분만 다른 출처로 바꿀 수 있게 한다.

## 위젯 모양

- 4×2칸, 3열×2행 타일. 순서: 달러, 엔화, 비트코인 / 엔비디아, 버크셔B, 갱신 칸.
- 자산 타일: 첫 줄에 아이콘(약 20dp, 원형) + 이름, 둘째 줄에 굵은 가격, 셋째 줄에 색 있는 변화.
- 갱신 칸: 오른쪽 아래 정렬. `16:21` + 새로고침 아이콘, 그 아래 "눌러서 새로고침".
- 새로고침 중에는 갱신 칸 시각 자리에 "갱신 중…"을 표시한다.

숫자 형식:

| 자산 | 가격 | 변화 |
|---|---|---|
| 달러 | `1,344.22` | `▲2.20 (0.16%)` |
| 엔화 100엔 | `841.50` | `▼0.10 (0.01%)` |
| 비트코인 | `8,206만` (만 원 단위, 반올림) | `▼166만 (1.99%)` |
| 엔비디아 | `$165.05` | `▲39.52 (31.48%)` |
| 버크셔B | `$572.36` | `▲2.36 (0.41%)` |

%는 소수 둘째 자리, 부호는 ▲/▼ 기호로만 표시한다.

## 갱신 방식

- 15분마다 주기 작업으로 전체 시세를 가져온다(안드로이드 주기 작업의 최소 간격). 네트워크가 있을 때만 실행하고, 재부팅 후에도 유지한다.
- 위젯 탭 시 즉시 한 번 가져온다.
- 위젯을 처음 홈 화면에 놓을 때도 즉시 한 번 가져온다.
- 화면이 꺼진 동안 삼성 절전 기능 때문에 갱신이 늦춰지는 건 받아들인다. 화면을 켜고 탭하면 바로 갱신된다.

## 제약

- 폰만으로 설치·업데이트할 수 있어야 한다.
- 앱 권한은 인터넷(그리고 재부팅 후 주기 작업 유지에 필요하면 그것)만 쓴다.
- 의존성은 최소로 한다. 플랫폼 기능(HTTP, JSON 파싱, 작업 예약, RemoteViews)으로 되는 건 라이브러리를 추가하지 않는다.
- 비밀값(API 키 등)은 없다.

## 검토한 대안

- **토스증권 Open API**: 사용자가 키를 줄 수 있다고 했으나 쓰지 않기로 함. 등록된 고정 IP에서만 호출할 수 있어 모바일 네트워크의 폰에서는 막힌다(토스 FAQ에 명시). 비트코인과 엔화 환율이 없다. 같은 키로 주문까지 가능해 폰에 넣기 위험하다.
- **위젯 모양 A(목록형), C(한 줄 띠형)**: 시안으로 비교 후 B를 선택.

## 빌더에게 맡기는 것

- 언어와 빌드 설정(Kotlin, Gradle, minSdk/targetSdk 등)
- 주기 작업에 쓸 API(JobScheduler, WorkManager 등)와 탭 새로고침 구현 방식
- 위젯 레이아웃의 정확한 dp, 글꼴 크기, 모서리 반경. 시안의 느낌(어두운 반투명, 둥근 타일)을 따른다.
- 로고 이미지 출처와 형식(앱에 내장, 인터넷 없이 표시)
- 런처 화면(앱 아이콘) 유무. 없어도 되지만, 있다면 위젯 추가 방법과 배터리 설정 안내 정도만.
- GitHub Actions 워크플로 세부(어떤 브랜치 푸시에 Release를 갱신할지 등)
- 시세 계산 로직에 대한 작은 자체 테스트
